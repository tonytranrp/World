# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## What this is

World is a single-player, first-person destruction sandbox built in Rust on Bevy. Everything visible is made of 1/64 m voxels. The world is a sparse 64-tree rendered by ray tracing in compute shaders, never meshed. Rapier handles physics. Targets are Windows and macOS.

The full design lives in `docs/plans/engine-plan.md`. Read it before making architectural changes. Decisions made after it are recorded in `docs/decisions/`.

## Layout

| Path | Role |
| --- | --- |
| `crates/Foundation/` | Bevy-free crates: `World_Core`, `World_Gen`, `World_Cpu_Ref` |
| `crates/Engine/` | Bevy plugins: `World_Render`, `World_Physics`, `World_Anim`, `World_Sim` |
| `crates/Game/` | Gameplay: `World_Game` |
| `app/` | The binary: CLI, settings, startup, plugin assembly |
| `tools/` | `Xtask`, `Bake_Vox`, `Mesh_To_Voxel` (offline, never shipped) |
| `assets/` | Runtime content: WESL shaders, RON config, rigs, models, audio, UI |
| `tests/` | Workspace-level golden images, scenes and replays |
| `packaging/` | macOS and Windows packaging metadata |
| `scripts/` | Small developer and CI helpers |
| `docs/` | Plans, decisions, architecture notes, research, devlog |

Every folder has a `README.md` that states its permanent purpose, scope and rules. Read the README of the folder you are about to change.

## Rules

1. **Dependency direction is one way:** Foundation <- Engine <- Game <- app. Never import upward.
2. **Foundation crates have no Bevy dependency.** If something needs Bevy, it belongs in `Engine/` or higher.
3. **Rapier is named only inside `World_Physics/src/rapier`.** Swapping physics engines must touch one crate.
4. **Shared constants live in `World_Core` only.** Shader copies are generated by `Xtask` codegen, never edited by hand.
5. **The CPU 64-tree is the source of truth.** The GPU mirrors it. Never let GPU state become authoritative.
6. **Worldgen is deterministic.** Same seed and chunk coordinate give identical voxels on every machine. Saves store edits only.
7. **No meshing of the world.** Triangles are for UI, gizmos and proxy boxes only.
8. **Each Bevy crate exposes one public `Plugin` and a `prelude`.** Everything else stays crate-private unless another crate needs it.
9. **Prefer deep module folders inside the existing crates** over creating new crates. New crates are rare because hot-patching works best with few of them.
10. **Tune with data first.** Materials, physics constants and worldgen parameters go in RON files under `assets/config/`, not in code.

## Naming

- Crate folders are `Pascal_Case` (`World_Render`). Package and crate names are `snake_case` (`world_render`).
- Module folders and files inside `src/` are `snake_case`.
- Top-level organizational folders are lowercase.

## READMEs are fixed

The folder `README.md` files are written once and describe intent, not contents. Do not edit them to reflect new files or progress. If a folder's purpose genuinely changes, record a decision in `docs/decisions/` first and then update that README as part of the same change.

## Large files

Binary assets (`.vox`, baked voxel files, images, audio, fonts) are stored with Git LFS, configured in `.gitattributes`. Run `git lfs install` once per clone.

## Testing expectations

- Core logic is covered by unit and property tests, checked against simple reference implementations (dense array, brute-force DDA, `World_Cpu_Ref`).
- ECS behavior is tested with a headless `App` and schedule randomization turned on.
- Physics uses deterministic replay with recorded hashes.
- Rendering is checked against golden images and exact CPU-vs-GPU hit comparisons on small scenes.
- Run the relevant tests before reporting work as done, and report failures with their output.

## Building and running

Cargo manifests, CI and packaging scripts are added after the skeleton. Until they exist there is nothing to build. Once they do, `Xtask` is the entry point for codegen, benchmarks and packaging, and the app accepts `--backend` and `--mac-floor`.
