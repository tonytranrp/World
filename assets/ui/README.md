# UI

## Purpose

This folder holds the visual resources for the game's interface: fonts, icons and images used by menus, the heads-up display and debug panels. UI is the one place where triangle-based rendering is allowed, so these assets are ordinary 2D resources drawn through Bevy's UI and sprite systems and composited over the voxel image.

## Scope

- Fonts for menus, HUD text and debug overlays.
- Icons: tool and inventory icons, material swatches, status indicators.
- UI images: backgrounds, panel frames, crosshair and cursor graphics, loading and title art.
- Atlases or slicing information when UI images are packed together.

## Out of scope

- Layout, widgets and interaction code. Those are Bevy UI systems in `World_Game`.
- Voxel models used for in-world objects, including held tools. Those belong in `assets/models`.
- Sounds for UI feedback that are material-agnostic belong with other sound assets in `assets/audio`.
- Developer-only inspector panels, which are generated by bevy-inspector-egui and have no assets.
- Shader code for compositing UI. That lives in `assets/shaders/passes/composite`.

## Relationships

- Loaded through the asset server by `World_Game`, rendered by Bevy on top of the voxel output after the composite pass.
- Icons that depict materials should follow the material table in `assets/config`.
- Bundled by `packaging/`.

## Rules

- Images and fonts are stored through Git LFS.
- Icons are authored at one consistent size family and scale cleanly to the 3072x1920 panel class; UI scale is a runtime setting, not baked into images.
- Fonts must have licenses permitting redistribution; license text travels with the font.
- UI art never relies on the voxel renderer; it must render correctly even if the world is not drawn (menus, errors on unsupported hardware).
