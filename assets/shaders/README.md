# Shaders

## Purpose

This folder holds all GPU shader code, written in WESL (WGSL Extended), which adds modules, imports and conditional compilation to WGSL. The renderer does not draw triangle meshes for the world. It traces rays through a sparse 64-tree in compute shaders, so almost all rendering logic is here rather than in Rust. Shaders hot-reload through the asset file watcher.

## Scope

- `common/`: modules shared by every pass: constants mirrored from `World_Core`, math helpers, bit packing and unpacking, and material table lookup.
- `traversal/`: the tree traversal library shared by all passes: sparse 64-tree walking with child masks, DDA stepping, mip-level stop for distant rays, brick-request feedback writes for the ray-guided brick cache, and box-march for dynamic grids.
- `passes/`: one folder per render pass, mirroring the pass layout in `World_Render/src/passes`: primary, dynamic_box, lighting, reflections, upscale and composite.

Pass folders contain entry points; reusable logic is moved into `common/` or `traversal/` and imported.

## Out of scope

- Pass setup, bind group layouts, pipeline creation and dispatch sizes. Those are Rust in `World_Render`.
- Tunable numbers that should be changed at runtime. Those are RON in `assets/config`.
- Shader constants authored by hand that duplicate Rust values. Constants shared with Rust are generated by `tools/Xtask` from `World_Core`.
- Triangle-mesh shaders for the world. Only UI, gizmos and proxy boxes use triangles, and those use Bevy's own materials.

## Relationships

- Loaded by `World_Render`, which compiles per-tier variants using WESL conditional compilation (tier A hardware-RT extras, tier B compute baseline).
- Binary layouts of nodes, bricks and the feedback buffer are defined in `World_Core` and mirrored here, so changing one means regenerating the other.
- The CPU reference tracer in `World_Cpu_Ref` defines the correct result; shader traversal must match it exactly on test scenes.

## Rules

- Never copy traversal logic into a pass; import it.
- Every module has a single responsibility and explicit imports.
- Generated constant modules are never edited by hand.
- Code must run on compute-only adapters (tier B); anything needing ray queries or mesh shaders sits behind a conditional.
