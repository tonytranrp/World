# Shader Common

## Purpose

This folder holds the low-level WESL modules that every shader may import: the vocabulary that makes the GPU code agree with the CPU data. It contains no pass logic and no traversal; it is the foundation those are built on.

## Scope

- Constants mirrored from `World_Core`: voxel size, tree branching (4x4x4), node and brick layouts, bit-field widths, sentinel values and limits. These modules are generated by `tools/Xtask` codegen.
- Math helpers: vector and matrix utilities, ray and box intersection primitives, safe reciprocals for DDA, hashing and low-discrepancy sequences used by lighting.
- Packing and unpacking: child masks, material ids, normals, motion vectors and G-buffer fields in their compact encodings.
- Material lookup: reading color, roughness, emission and other fields from the material table buffer by u16 material id and through per-node palettes.

## Out of scope

- Tree walking, DDA stepping and box-march. Those belong in `../traversal`.
- Per-pass entry points and bindings. Those belong in `../passes/<name>`.
- Tunable values. Those are RON in `assets/config`.
- Rust-side struct definitions and buffer creation. Those belong in `World_Core` and `World_Render`.

## Relationships

- Imported by `../traversal` and by every pass module.
- Generated constants depend on `World_Core` through `tools/Xtask`; a layout change in Rust regenerates the shader modules, and CI should detect drift.
- Material fields match the table defined in `assets/config` and loaded by `World_Render`.

## Rules

- Generated modules are marked as generated and never edited by hand.
- Nothing here may depend on `traversal` or `passes`; dependencies point one way.
- Functions are pure and free of resource bindings where possible, so they can be tested and reused across any pass.
- Packing formats are documented beside their code and must stay symmetric: every pack has a matching unpack.
- Keep everything valid on tier B (compute-only) hardware.
