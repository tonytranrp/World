# Models

## Purpose

This folder holds authored voxel content: the hand-made and converted voxel models used for the player, held tools and props. World terrain is not authored here; it is generated by `World_Gen`. Models are the content that artists and the bake tools produce.

## Scope

- MagicaVoxel `.vox` source files, which are the editable originals.
- Baked output produced from those sources by `tools/Bake_Vox`: dense voxel grids with palette and material mapping, ready to load as dynamic-object grids with no further processing.
- Voxelized output of triangle meshes produced offline by `tools/Mesh_To_Voxel`.
- Per-model metadata such as pivot, voxel scale (for example finer 1/128 m for hand-held items) and part names.

The content is organized into three subfolders by role: `player/` for the player body parts, `tools/` for held tools, and `props/` for placeable and scattered objects.

## Out of scope

- Terrain and any content the worldgen pipeline produces from a seed. That is code and parameters in `World_Gen` and `assets/config`.
- Skeleton and bone definitions. Those live in `assets/rigs`; models here are only the parts that rigs reference.
- Triangle meshes as shipped content. Meshes exist only as offline inputs to `Mesh_To_Voxel`.
- Test-only models. Those belong in `tests/scenes`.

## Relationships

- Sources are consumed by `tools/Bake_Vox` and `tools/Mesh_To_Voxel`; baked files are loaded at runtime by `World_Game`, `World_Anim` (parts bound to rig bones) and `World_Physics` (collision grids derived from the voxels).
- Material ids in a model's palette must resolve against the material table in `assets/config`.
- Bundled by `packaging/`.

## Rules

- All `.vox` files and baked voxel files go through Git LFS.
- Baked output is reproducible from its source and tool settings; it is never hand-edited.
- Model scale is stated in metadata and never inferred from file dimensions.
- Dynamic objects stay small dense grids, sized so a part can be rendered by box-march and given a collision grid.
